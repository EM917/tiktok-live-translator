# 中英双语界面：给维护者的说明

2026-09-28 用户决定做英文界面，2026-09-29 开闸（Z1）。界面文字由程序在「发往界面」的那一刻
按语言挑中文或英文；终端、日志、审计永远是中文。英文怎么写（术语、大小写、标点、定稿文案）
看 `docs/i18n-style.md`，这份只讲机制。

## 1. 一句中文带着它的英文

- Python：`L("中文", "English")` 的结果**就是那句中文**（`str` 的子类 `Bi`），英文挂在 `.en` 上。
  `==`、`in`、`print`、`json.dumps`、写审计全按中文走，所以终端和审计与没加 `L` 之前逐字节相同。
- 英文只在出口换出来：桌面广播和 hello 回放（`app/server.py`，`i18n.render`）、手机消息
  （`app/viewer.py filter_payload`，派生 `text_en` / `why_en`）、原生窗口标题、关窗确认框、
  系统通知、启动期对话框（`i18n.text`，交给系统的永远是普通 `str`）。
- 前端：`web/i18n.js` 的 `L()` / `LN()` 按页面 `<html lang>` 取一边；静态 HTML 的英文写在
  `data-en*` 属性上，英文页加载时 `applyStatic` 换进去。手机页用 `web/viewer.js` 自带的一份。
- 英文写坏（占位符对不上）只会退回中文，绝不抛异常，终端打一行 `[i18n]`。测试里是 strict，
  当场红。

## 2. 界面语言怎么定

`app/i18n.py` 按下面的顺序取，取到就停：

1. **一次性覆盖**：命令行 `--ui-lang zh|en` 或环境变量 `TLT_UI_LANG`。不写设置，用于截图和开发。
   带了它，设置行的下拉会置灰，悬停提示「由启动参数固定」。
2. **发布闸** `I18N_ENABLED` 为 `False`：恒为中文（回退时就是这个状态）。
3. `settings.json` 的 `ui_lang` 为 `zh` 或 `en`：就用它。
4. `ui_lang` 为 `system`：跟系统语言。macOS 先看系统设置里给本 App 单独选的语言，再看全局首选
   语言；Windows 看显示语言；其它平台看 `LANGUAGE` / `LC_ALL` / `LC_MESSAGES` / `LANG`。
   首项以 `zh` 开头（含繁体）是中文，其余是英文；检测不了按中文。每次启动只检测一次，
   结果经环境变量 `TLT_SYSTEM_LANG` 带过 exec。

初始化分两步，顺序不能乱：

- `boot(ROOT)`：`main.py` 开头，每个进程都跑，**只读**。记下装机状态（第一个进程看到
  `settings.json`，或 `.venv` 里有「装成功过」的记号 `.requirements.sha256`，就是老装机，记在
  `TLT_INSTALL_STATE`），给自举期的对话框定语言。
- `settle(ROOT)`：exec 进 `.venv`（macOS 上再进 `.app`）之后的最终进程里跑一次，这里才第一次
  `load_settings()`、才写设置。提前读会让损坏的 `settings.json` 在前一个进程里就被改名备份，
  「设置文件损坏，已备份为…」的提示和审计里的备份名随 exec 丢掉。

## 3. 老装机固定中文，只有新装跟系统

开闸后第一次启动时，设置里还没有 `ui_lang`，`settle` 写一次（用户 09-28 的决定）：

| 装机 | 写什么 | 结果 |
|---|---|---|
| 已有 `settings.json`，或 `.venv` 装成功过（老用户升级） | `"zh"` | 界面保持中文，不会因为系统是英文就突然变 |
| 都没有（新装） | `"system"` | 跟系统语言 |
| 新装、界面解析为英文、从没选过翻译目标语言 | 另写 `target_lang = "en"` | 第一次启动字幕就译成英文 |

「装成功过」看的是 `.venv/.requirements.sha256`：bootstrap 只在 `pip install -r` 返回 0 之后才写它。
光有 `.venv` 目录不算老装机——`setup.sh` / `setup.ps1` 一开头就建 `.venv`，再用它跑
`main.py --doctor`（这就是第一次迁移）；第一次启动装到一半失败（断网、中途退出）也会留下
`.venv`。这两种都还没真正用过，算新装。真正用过的安装都有 `settings.json`（进过直播间就记
`room_url`，后台更新 yt-dlp 成功也会记下时间）。

只在闸开着时迁移：闸关着那几周装上的机器没被写成 `system`，开闸后照样算老装机。
`settle` 结束时把 `TLT_INSTALL_STATE` 改成 `existing`，一键更新重启（execv 继承环境）不会
再按新装判一次。

## 4. 设置行

「设置」分组最后一行「界面语言 · Language」：跟随系统 / 中文 / English。设置分组在直播中和
连接中整块隐藏，所以只能在待机时切换，不会打断监听。

切换时：存进 `settings.json` → 广播新的语言字段 → 所有桌面页面发现语言和自己不同，整页重载
一次（`sessionStorage` 防止来回重载）。

| 什么 | 什么时候跟着变 |
|---|---|
| 桌面全部文字，包括重连时回放的旧消息 | 立即（重载后） |
| 窗口标题、后台报警时的标题、关窗确认框 | 立即：页面重载后经 JS 桥调 `set_window_lang`。pywebview 5 上关窗框要重启才换 |
| 系统通知 | 下一条起 |
| 启动期对话框 | 下次启动 |
| 手机同看页 | 不受影响，见下一节 |
| Dock、菜单栏、⌘Tab 里的程序名 | 不跟设置行，跟 macOS 系统语言（见下） |
| 终端、日志、审计 | 永远中文 |

下面这几样都在这套机制之外，看不到闸，也读不到设置（N1 提交）：

- **程序名**：`Info.plist` 带三份 `InfoPlist.strings`（`Contents/Resources/en.lproj`、
  `zh-Hans.lproj`、`zh-Hant.lproj`），系统按自己的语言挑：中文系统（简体、繁体都算）叫
  「TikTok 直播同传」，其余叫 TikTok Live Translator。`zh-Hant` 那份也写简体：界面把 `zh` 开头的
  系统语言都当中文，繁体系统上界面是简体中文，程序名跟界面一致；少了它，繁体系统会退到英文名。访达照旧显示文件名 `TikTok Live Translator.app`：故意不设
  `LSHasLocalizedDisplayName`，程序和 README 里「双击 TikTok Live Translator.app」的指引
  才对得上（用户决定 2、5）。LaunchServices 有缓存，改了之后可能要重新登记一次才更新。
- **`.app` 启动器和 `Start.command` 的出错对话框**：在 Python 之前弹出，中文一段、英文一段
  并列，标题 `TikTok 直播同传 · TikTok Live Translator`，按钮 `OK`。`Start.command` 的终端
  说明保持中文（用户决定 4）。
- **直接双击 `web/index.html`**（file://）：什么都加载不出来，内联脚本给的指引和标题同样中英并列。

`tests/test_mac_bundle.py` 钉着前两样：两份 strings 的键值、`Info.plist` 里没有
`LSHasLocalizedDisplayName`；启动脚本用 bash 真跑，PATH 里只放假的 `osascript` / `open`，
逐字比对话框的 AppleScript。

## 5. 手机同看页

看手机的人和电脑前的中控往往不是同一个人，所以手机页**跟手机自己的语言**，与桌面无关：

- 服务端按手机浏览器的 `Accept-Language` 写 `<html lang>`，另加 `data-i18n="on"`。
  `viewer.js` 见到这个标记才读本机的选择、才显示底栏的语言切换（显示另一种语言的自称：
  `EN` / `中文`）。手机上的选择存在那台手机的 `localStorage`（`tlt.viewer.lang`）。
- 事件提示和字幕、报警的原因说明随消息带两份：`text` / `why` 是中文，`text_en` / `why_en`
  是英文。所有手机共用同一份消息，各挑各的。
- 闸关着时手机页是文件本身，消息一个字段都不多。

## 6. 不英文化的东西

- 终端和控制台输出、日志、审计 JSONL；`Start.command` / `Start.bat` 里的说明文字。
- 数据：主播名、观众名、品牌名、违禁词表和各词表的内容、报警里的词条、字幕和弹幕的原文译文、
  翻译目标语言下拉（选项本来就是各语言的自称）、文件名、模型名。
- 浏览器的「翻译此页」照样能翻字幕、弹幕和报警原话（用户 09-29 的决定）；
  `translate="no"` 只标名字类数据。
- `tools/` 下的命令行工具。

## 7. 加一句新文案

1. 写成对，中文照常写，英文写在旁边：

   ```python
   from .i18n import L, LN, of, bimap

   # 例子取自 app/pipeline.py、app/pipeline_disk.py、app/viewer.py、app/pipeline_engine.py
   await self.server.status("error", L(
       "内部错误，已停止：{}",
       "An internal error stopped monitoring. Details: {}").format(of(exc)))   # 异常文字用 of(exc)
   text = LN(len(done), "已删除 {} 项，释放 {}", "Deleted 1 item and freed {1}.",
             "Deleted {0} items and freed {1}.").format(len(done), size)       # 英文按数量挑一句
   ips_text = L("、", ", ").join(ips)                 # 分隔符也写成对
   short = bimap(lambda s: s[:120], error)            # 截断、清洗：中英两句各做一次
   ```

   ```js
   btn.textContent = L("保存", "Save");
   ```

   ```html
   <button id="save" title="保存设置" data-en-title="Save settings" data-en="Save">保存</button>
   ```

   会把英文丢掉的写法：f-string、普通字符串的 `"…{}".format(bi)`、切片、`.strip()`、`re.sub`、
   `str(exc)`、普通字符串的 `"sep".join(...)`。它们得到的是普通中文 `str`，英文界面上就露那一句
   中文。异常用 `raise X(L(...))` 抛、用 `of(exc)` 取。
2. 用 `docs/i18n-style.md` 的术语；同一句中文全仓只能有一种英文，确实要不同的登记在
   `tests/i18n_rules.py` 的 `SAME_ZH_DIFFERENT_EN` 并写理由。句子里提到按钮名「X」时，英文里
   要出现同一个按钮的英文名（`UI_NAMES`）。
3. 不上界面的中文不用成对：以 `[信息]`、`[警告]` 这类标签开头的终端行自动豁免，其余在行尾写
   `# i18n: terminal`（或 `audit` / `data` / `os`）。
4. 新文件会产出界面文字：文件头写 `i18n: done`（Python `# i18n: done`、JS `// i18n: done`、
   HTML `<!-- i18n: done -->`），并加进 `tests/i18n_rules.py` 的 `UI_FILES`。
5. 跑检查，都看退出码：

   ```bash
   python3 tools/i18n_pairs.py             # G2 成对、G3 同中文同英文、G4 覆盖；--list 逐条列出
   python -m pytest tests/ -q              # 除 G6、G10 以外的闸都在里面
   node --test tests/*.test.mjs            # G6：前端纯函数的英文
   ```

   G10（无头 Chrome 打开英文页扫 DOM，不许剩中文，还量顶栏宽度）默认跳过，要
   `TLT_DOM_SCAN=1 pytest tests/test_i18n_dom.py -q`。它开一整个浏览器进程，**直播转写进行中的
   机器上不要跑**（先 `pgrep -f tiktokcdn`），交给 PR 的 CI dom-scan job。

  `False`。桌面、手机页、手机消息、原生窗口一起回到开闸前的样子，不用回退任何迁移提交；
  测试不用跟着改（守闸某一边语义的测试都显式设了闸）。N1 若已合入，一并 revert。
  整个提交 revert 会把 CLAUDE.md 第九条和这份说明一起撤掉；只想关掉英文界面、留着规矩
  （新文案照样成对写），只把那一行改回 `I18N_ENABLED = False`。
- 设置里留下的 `ui_lang` 没有影响：闸关着时不读它。新装机被 T 写上的 `target_lang = "en"`
  留着：那是翻译目标语言，用户在下拉里随时能改。
- **只是某台电脑想要中文**：设置行选「中文」；只这一次启动：`--ui-lang zh`。
