# 标注指南（base LoRA 训练目标）

标注的是「**这句西语单独说出来，中控该看到的中文**」。第 1 天和第 5 天的
标准必须一样——拿不准就回来读这一页。

## target 硬规则

1. **只翻当前 source 单独能推出的信息。** 上下文（前后句）只用来帮你判断
   这句是不是碎片、ASR 有没有坏——只有靠上一句才能确定的主语/价格/指代，
   一律按 `context_required` 排除，**绝不能**把上下文里的信息写进 target。
   那是在教模型猜。
2. **数字、价格、数量关系必须完整且准确。** 30 美元门槛不能变成 30 瓶，
   "最高 70%" 不能丢掉"最高"。数字写阿拉伯数字。
3. **不补 source 没说的信息。** 说了一半的话就译一半（用……收尾），
   不替主播把话说完。
4. **中文要自然、简洁、像给中控看的字幕**，不逐词直译；语气词可以省，
   意思不能偏。
5. **主播专属知识不进 base target。** 品牌名、SKU、主播自创的商品昵称
   （如 gotitas 指某家的具体产品）→ 按 `profile_only` 标记，这条留给
   profile/glossary 资产，不进 base 训练集。

## 按钮语义

| 动作 | 什么时候用 |
|---|---|
| `accept_local` | 本地快译已经完全达标，原样采纳 |
| `accept_strong` | 强译参考达标，采纳 |
| `manual` | 两个参考都不达标，人工写 target（遵守上面 5 条） |
| `asr_garbage` | source 本身是识别坏句（乱码/幻觉/拼接错），不标 |
| `context_required` | 单看这句写不出确定的译文（主语/指代/价格关系悬空） |
| `profile_only` | 内容依赖主播专属品名/SKU，留档 profile 资产 |
| `skip` | 近重复、无信息量、或当下拿不准（可回头再看） |

## 流程纪律

- 先标 **100 条 pilot** → 隔一天随机抽 20 条自己重新盲标 → 对比一致性、
  检查按钮定义有没有歧义 → 没问题再推进到 300–400 条。测试的是流程，
  不是模型。
- 参考译文只显示许可明确的本地/开源引擎；`withheld` 的参考不是漏了，
  是刻意隔离（provenance）。
- holdout 清单（eval_holdout.json）里的 session/主播永远不会出现在
  队列里；如果看到了，说明管线出 bug，立刻停下来报告。
